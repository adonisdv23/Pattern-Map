# The Echo Problem: When Repetition Masquerades as Corroboration

**Project code:** ECHO-01
**Curated identity:** EP v0.1
**Status:** preserved internal owner-review successor; unrun; no results; not published

The Echo Problem is a focused origin-accounting research track. It asks a
bounded question for future work: when several reports repeat the same claim,
what can be said about their relationship, and what must remain unknown, before
repetition is treated as independent corroboration? The project separates
observation count, common origin, claim support, authority, relevance,
permission, and truth. It does not turn any one of those dimensions into a
universal trust score.

This successor begins at **EP v0.1**. It is derived from the exact v15.2
checkpoint recorded in the accession under
`archive/transfers/v15.2-owner-handoff/`; v15.2 itself remains historically
named and byte-preserved. The successor adds orientation, versioning, a formal
relationship to v16, status boundaries, and a future low/no-cost execution
plan. It does not rewrite the preserved manuscript, site, protocol, harness,
fixtures, or prior-art records.

## What this project is not

The Echo Problem is not the opening or definition of v16, not a completed
paper, not a validation result, not a claim that origin accounting is novel,
and not permission to call a model, acquire a dataset, contact participants,
publish, deploy, or take an externally consequential action. The broad v16
thesis and all six families must remain understandable if this project is
removed.

## Current decision boundary

The only current work is preservation, curation, and verification. The
accessioned source records a local owner-review package with no empirical
results, zero model/provider study calls, zero participants, and no acquired
external dataset. A passing hash or offline test is an integrity result, not a
research result. Unknown origin relations remain unknown; a human hold or
quarantine remains a disposition, not a fact about the claim.
