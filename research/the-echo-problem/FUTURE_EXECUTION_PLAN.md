# EP v0.1 future low/no-cost execution plan

This is a planning document, not an authorization and not a report of work
performed. The sequence below is intentionally local and low/no-cost first.
Every stage that could become a model, empirical, participant, or external
action requires a later exact owner instruction and its own evidence record.

## Proposed sequence

### Design checkpoint before any live work

EP v1.1 records Amendment A1 as **adopted with the NEWS-COPY narrowing**, not
as written wholesale. NEWS-COPY is an optional same-original/origin-cluster
validation route only; Newswire is aggregate context only; unknown relations
stay unknown. The controlled F0/F1/F2 design remains the first-paper candidate.
A typed, real-world measurement instrument is a prospective second-paper
candidate and must first pass the targeted prior-art matrix, labelled threshold
validation, rights/version review, and a separate owner decision.

### 0. Reconfirm the checkpoint

Re-run the owner-intent checksum, accession verifier, and preserved-source
verifier from a clean checkout. Confirm that the source ZIP sidecar, external
manifest, source commit, and payload counts still match. This is integrity work,
not a study.

### 1. Exercise only deterministic local machinery

If authorized, run the preserved offline unit tests and schema checks against
the retained synthetic fixture contract. Do not call a model or provider, do
not acquire a dataset, and do not interpret a passing test as evidence that
origin accounting improves decisions. The v15.2 fixture directory currently
contains its README contract, frozen configuration, and schemas; it does not
contain a claimed empirical fixture dataset.

### 2. Audit the protocol before any live condition

A future owner review should freeze the question, estimand, denominators,
invalidity policy, safety subset, origin relation labels, unknown/hold rules,
matched-budget comparison, and stop/quarantine gates. The audit should preserve
the full unfavorable-result space listed in `STATUS_AND_BOUNDARIES.md` and
should not let parsing success, report count, or a threshold alone become a
claim of corroboration.

### 3. Optional model study, only after separate authorization

If the owner later authorizes a model study, the plan should name the provider,
model, budget, access and permission boundaries, frozen prompt/configuration,
logging and retention rules, safety review, and reproducible environment before
any call. Conditions should be matched on the stated budget and evaluated with
predeclared validity, audit, transfer, stability, harm, and stop criteria. No
provider is selected by EP v0.1, and no call is made in this branch.

### 4. Participant work is a separate gate

Any reader or participant study is outside this lane's current authority. It
would require a separate owner decision covering ethics or exemption,
consent, recruitment, compensation, privacy, accessibility, data retention,
and participant safety. No outreach or participant activity is planned as a
current action.

## Stop and interpretation gates

- If the source or permission relation is unknown, record `UNKNOWN` and hold;
  do not infer from recurrence or technical access.
- If parsing, schema, or validity fails, preserve the failure and classify it as
  `invalidity_driven` where applicable; do not silently repair the denominator.
- If a shortcut or surface cue can explain the result, classify it as
  `shortcut_driven` or `surface_or_semantic_audit_failure` and quarantine the
  interpretation.
- Stop on material harm, unbounded privacy/security risk, or an authorization
  boundary breach.
- Treat instability, noise fragility, and non-transfer as findings that limit
  scope, not as inconvenient runs to omit.
- Report null and rule-only outcomes with the same care as favorable outcomes.
- A threshold, recurrence count, or provenance link alone cannot establish
  claim support or truth.

## Cost boundary

The current work uses local files and standard-library verification only. No
paid provider, model quota, external dataset, participant incentive, or
publication/deployment channel is assumed. A future expansion must state any
new cost and obtain permission before incurring it.
