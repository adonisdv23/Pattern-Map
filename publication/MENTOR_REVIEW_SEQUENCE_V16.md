# Private mentor review sequence — Pattern Map v16

Status: **UNSENT OWNER FACILITATION NOTE — NO MENTOR CONTACT HAS OCCURRED**

This is a short sequence for a later, private owner-led conversation with the
author's mentor or another thoughtful reader. It is intentionally lighter than
the full owner-review packet. The desired result is a better question, a
counterexample, or a bounded next edit—not a ceremonial sign-off and not a
claim of measured comprehension.

Use the local public preview or the canonical manuscript as the reading
surface. Keep the reviewer's words separate from the author's interpretation.
Do not send this file, a link, or a message until a later explicit owner
instruction authorizes that contact.

## Before the conversation

- Build the current site and run its checks from the exact current branch.
- Open the local public [Read route](../site/exports/standalone/pattern-map-v16-public.html#read)
  or the [60–90-second manuscript](../manuscript/NINETY_SECOND_VERSION.md).
- Have the current [six-family Map](../site/exports/standalone/pattern-map-v16-public.html#map)
  and the [Boundaries route](../site/exports/standalone/pattern-map-v16-public.html#boundaries)
  available as optional follow-ups.
- Keep the [mentor cover note](../manuscript/MENTOR_COVER_NOTE.md) as context,
  not as a script the reviewer must endorse.
- Start a fresh response sheet. Do not prefill a positive judgment.

The time ranges below are editorial planning estimates, not observed reading
times. If the reader wants to stop after the first pass, stop there.

## The sequence

| Pass | Surface | Ask one question | Record as an observation |
| --- | --- | --- | --- |
| 1 · Enter the problem (2–4 min) | Short version or public Read opening | “What do you think is happening before the answer is written?” | The reader’s words, including uncertainty or a narrower interpretation |
| 2 · Test the breadth (5–8 min) | Map, only after the opening | “Which of these six ways of seeing upstream choices feels most useful, least clear, or missing?” | A concrete family, example, or missing comparison; do not remove a family because one example is weak |
| 3 · Test proportion (3–5 min) | Apply route, starting at Stage 0 | “Where would you keep ordinary work ordinary, and where would one extra record earn its cost?” | A proposed boundary or stopping condition; Apply is planning-only and records no run |
| 4 · Test the examples (3–6 min) | Examples route | “Does the specialist signal, baseline/absence example, and common-origin example each teach a different thing?” | Which example clarifies or confuses; common origin must remain a bounded F5 example |
| 5 · Test the claim ceiling (3–5 min) | Boundaries, Sources, optional Research | “What sounds stronger than the evidence allows, and what question would you test next?” | A phrase to narrow, a source route to recheck, or a future test question—not a result |
| 6 · Close the conversation (1–3 min) | Cover note or the first screen again | “What would you challenge or expand if this were the start of a longer conversation?” | The invitation, objection, or next question; no acceptance status is inferred |

The sequence is complete when the reader has either offered a challenge or
chosen to stop. It is not complete because every route was opened.

## Response sheet

Copy this small table for each substantive comment. Keep the first column as
the reader’s words or a faithful short excerpt; put interpretation in a
separate column.

| Reader observation (or short excerpt) | Author interpretation (separate) | Affected artifact/route | Next disposition |
| --- | --- | --- | --- |
|  |  |  | `OPEN` / `OWNER DECISION REQUIRED` / `FOLLOW-UP CHECK` |
|  |  |  | `OPEN` / `OWNER DECISION REQUIRED` / `FOLLOW-UP CHECK` |
|  |  |  | `OPEN` / `OWNER DECISION REQUIRED` / `FOLLOW-UP CHECK` |

An `OPEN` row is not a fact about the reader or the framework. Preserve a
disagreement rather than turning it into a stronger claim. A request to change
the locked proposition, six-family scope, human-authority boundary, or Echo
separation is an owner decision, not an automatic edit.

## Stop and safety conditions

Pause the sequence and record the question if any of the following occurs:

- The reader reduces v16 to origin counting or repeated-source detection. Return
  to the human problem and the six-family breadth; do not defend the protocol
  first.
- A peripheral item is treated as true because it is peripheral. Re-state that
  it is a candidate to inspect.
- A plan is described as an observed run, outcome, learning review, or human
  decision. Keep Apply’s `NOT_RUN`, `NOT_OBSERVED`, and `NOT_RECORDED` states.
- Someone asks to post, publish, deploy, choose the byline, choose a URL, or
  contact a person. Stop; use the release checklist only after explicit owner
  authorization.
- A proposed change would make the full framework mandatory for ordinary work.
  Return to Stage 0 and the proportionate-route boundary.

## What this sequence cannot establish

It cannot establish that the mentor agreed, that a public reader understood,
that the framework is effective, that a source is correct, or that a later
publication should happen. Those are separate human, evidence, and
publication-time decisions.
