## Synthetic cold-start QA honesty audit

The QA report has an honest evidence ceiling in several places:

- It labels itself “STRUCTURAL / PROCEDURAL QA ONLY” and explicitly says it is
  not a transfer or effectiveness result.
- It identifies the question as a synthetic cold-start contract test and says
  no real project was contacted.
- It says the matrix is structural, not an executable downstream router, not a
  project transfer, and not evidence that an agent follows the page.
- It says the checks establish artifact presence, phrase/field contracts,
  vocabulary, and selected fail-closed mutations only.

The following phrases should nevertheless be treated as claim-precision
defects if the target is integrated:

1. “reproduced friction” and “after reproduction” imply an observed receiver
   failure, but the only described operation is a reviewer-authored question
   and document composition exercise.
2. “wins the removal test” implies a validated comparative result. The removal
   section is a conceptual design test; existing Quickstart/templates still
   operate, and the target validator itself makes the new page a dependency.
3. “returns four fields and stops” describes intended operator behavior, not
   what the Boolean matrix executed.
4. “directs `MISSING_BASELINE`” is not supported by the starter text, which
   says only “no unsupported motion or absence claim; stop or narrow at the
   bound.”
5. “state-specific stop semantics” is broader than the five-case matrix,
   which has one `permission_resolution=True` case and does not distinguish
   `UNKNOWN`, `NOT_AUTHORIZED`, and `REVOKED` behavior.

These are P2 wording/representation corrections, not evidence that the
starter is useless. The report's disclaimers should remain, and a revised
report should describe a design hypothesis or structural contract check rather
than a transfer observation.

## Permission and completeness challenge

The target page correctly preserves the permission vocabulary, but the
handoff's field shape deserves a strict boundary:

```text
permission_scope_and_state:
```

This is acceptable as a human routing prompt only if it is explicitly a
summary that points to the existing operation-level permission envelope. It
must not become a compact replacement for the canonical rows. The canonical
receipt rule is stronger than the target sentence: for a blocked global state,
evidence, baseline, comparison, disconfirmation, memory, and influence are
empty, memory is `NOT_USED`, and blocked operations do not acquire, disclose,
reuse, or act. The target omits `baseline` and `NOT_USED` from its one-sentence
summary.

Likewise, the context block is a useful minimal handoff but not a complete
decision record. It carries consequence, reversibility, owner/reviewer,
deadline/outcome window, baseline, cost/no-action boundary, unknowns, and
family reasons. The existing brief still supplies useful-answer content,
abstention/escalation conditions, operation-specific permission, comparison
set, and complete route policy. A receiver that is told to “open only the
records named by the chosen route” must therefore remain inside the canonical
bundle and cannot infer that the starter alone makes the route complete.

## Removal and proportionality test

### Conceptual removal

Removing `PROJECT_USE_STARTER.md` leaves the existing Quickstart, copyable
brief, preflight, implementation choices, templates, and decision receipt
available. Stage 0, the ordinary escape, typed permission, the three levels,
family optionality, stopping, and learning remain defined. The only lost
convenience is the proposed project-context-to-template map. This supports a
bounded usability hypothesis, not a demonstrated necessity.

The target's own global validator makes the result internally inconsistent:
removing the page leaves the operating procedure usable but causes
`validate_artifact_inventory()` and `validate_project_use_starter()` to fail.
That is an implementation dependency, not evidence that the framework needs
the page. The smallest safe resolution is to make the page and its focused
check optional/local, or defer the artifact until the real-project condition
is satisfied.

### Proportionality

The starter is shorter than Quickstart and avoids copying the full ten-step
procedure. That favors a possible adapter. Countervailing burden includes:

- 14 new handoff fields that can be mistaken for a second context/permission
  record;
- a static validator with exact prose, field-order, vocabulary, and path
  coupling;
- a 193-line QA narrative that can be mistaken for transfer evidence despite
  its disclaimers; and
- a global inventory requirement that makes an explicitly non-mandatory page
  mandatory for repository validation.

The addition passes a narrow *conceptual* removal test only: it may reduce
translation effort for an as-yet-unobserved receiver. It does not pass an
observed cold-start transfer test. D-042's reduced-friction rule therefore
supports, at most, a repository-local owner-review candidate with no universal
or portable claim.

## Research/readiness and claim ceiling

No target text claims that the page improves decisions, validates v16, or
proves transfer. The QA report explicitly rejects those readings. The risk is
indirect: “materially different project,” “first cold-start page,”
“reproduced friction,” and “wins the removal test” can be quoted later as if
they were evidence of general project usability. They should be narrowed before
integration.

The target also does not establish any of the following:

- that a real project can enter v16 without reading the repository;
- that an agent or operator follows the page;
- that the chosen family or template set is complete for a receiver;
- that permission statements are legally or operationally valid in another
  project;
- that a cold-start adapter reduces time, ambiguity, or error;
- that Signal Foundry or the neutral cases transfer the starter; or
- that any framework arrangement improves decisions.

No new research result, selected study, provider/model, corpus, participant
plan, or outcome fixture is warranted by this review.

## Recommended integration disposition

The current target should not be accepted unchanged. The narrowest path that
could satisfy D-042 is:

1. treat the starter as an optional, repository-local owner-review candidate;
2. remove its unconditional global artifact dependency, or explicitly make the
   check opt-in and preserve the framework's validity when it is absent;
3. label the README/page as a proposed wayfinding adapter over the canonical
   bundle, not a portable adoption or transfer entry point;
4. correct synthetic-QA wording to structural/design-hypothesis language;
5. clarify that the permission field is a summary pointing to operation-level
   canonical rows, and align the blocked-state sentence with the receipt
   contract; and
6. retain the ordinary-work escape, optional-family rule, human authority,
   no-placeholder rule, typed states, and route/stop/learning separation.

If those revisions are not authorized, defer the starter under D-031/D-042
until repeated friction is observed in Signal Foundry and a materially
different second real project. Do not create a portable packet or call the
synthetic QA a transfer result.
