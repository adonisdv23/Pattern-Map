# V15.1 owner package map

This document is the navigation contract for
`PATTERN_MAP_V15_1_OWNER_REVIEW.zip`. The archive is organized for a human owner
or another GPT to understand the project without reconstructing the overnight
work from chat history.

## Which folder contains the final output?

Open **`01_FINAL_OUTPUT/`** first.

- `site/` is the canonical interactive website source.
- `visual-review/PATTERN_MAP_V15_1_REVIEW_COMPANION.pdf` is the 20-page
  untagged visual/print companion.
- `canonical-manuscript/THOUGHT_PIECE_V15.md` is the canonical long-form text;
  the compatibility filename remains v15, but its header identifies v15.1.

Open **`00_START_HERE/`** before editing anything. It contains the owner packet,
repository orientation, package map, and machine-readable package manifest.

## Instructions for another GPT

1. Read `00_START_HERE/OWNER_REVIEW_PACKET_V15_1.md` and this map.
2. Treat `01_FINAL_OUTPUT/site/` and the canonical manuscript as the current
   editorial surfaces.
3. Preserve the no-results boundary. The Lab is a protocol surface only.
4. Do not infer broad novelty. Read the current prior-art disposition before
   changing claims.
5. Preserve the v13 diagram unchanged as historical evidence of origin; do not
   use it as the current architecture.
6. Do not convert generated illustrations into empirical evidence.
7. Run the included offline checks before proposing changes.
8. Do not select/pay for a model, acquire external data, publish, deploy, or
   mutate GitHub without a new explicit instruction.

## Visual provenance

The package includes the full current image-candidate directory and
`IMAGE_SELECTION_LEDGER.md`. The ledger records the generating surface,
candidate role, selection decision, bounded use, and rejection reason where

## PDF boundary

The PDF is an untagged visual review companion. The semantic HTML and Markdown
are the accessible canonical surfaces. It was rendered locally and inspected
page by page. It contains no empirical result.

## Repository boundary

The archive is a handoff artifact, not a command to publish. The GitHub
checkpoint recommendation is read-only. No remote repository change is implied
by the presence of this package.
