# Domain-neutral case A — choosing whether to add a second weekly session

Status: ILLUSTRATIVE FIXTURE / NOT EMPIRICAL / NOT A RECOMMENDATION

This case shows how a small team might use the framework to decide whether to
pilot an additional weekly session for a community learning program. The
records and values are invented fixtures for procedure testing. They are not
attendance data, a study, a forecast, or evidence that the framework improves
the decision.

## Decision brief

- Decision: decide whether to run a four-week second-session pilot.
- Intended use: prepare a bounded recommendation for the program owner.
- Consequence: MEDIUM; reversible if the pilot is authorized.
- Owner: program owner, not the agent.
- Human authority: the program owner decides whether any pilot or new
  collection is authorized.
- Default path: use the existing attendance sheet and recent participant
  comments.
- Peripheral route: inspect a specialist scheduling note and a less-visible
  accessibility comment.
- Permission: supplied records only; no participant contact or new collection.
- Cost boundary: 25 minutes of review; no paid retrieval; one owner review.
- Stop: stop if the records cannot distinguish interest from capacity or if a
  staffing permission is missing.
- Outcome: if authorized, compare planned attendance and staff load with the
  four-week pilot record.

## Disconfirmation and route

- Leading interpretation: a second session may address an expressed need.
- Challenge: the comments may reflect one origin, and accessibility or staffing
  constraints may outweigh the request.
- Disconfirmation attempts: trace the two comments’ origin; inspect the
  accessibility note; check denominator and no-show definition; ask the owner
  whether staffing authority exists.
- Current route: ANSWER_PROVISIONALLY — “The supplied records contain repeated
  requests and a possible slot, but they do not establish independent demand,
  accessibility fit, staffing authorization, or likely pilot outcomes.”
- Escalation: program owner decides whether to authorize a pilot and any new
  collection.

## Outcome plan if separately authorized

Before a pilot, record:

- expected attendance range and how it is measured;
- staff hours and cancellation threshold;
- accessibility issue review;
- decision window and comparison to the existing session;
- what would lead to stop, continue, or revise.

Afterward, preserve the original expectation and compare the observed outcome.
An outcome could motivate a bounded update to scheduling criteria; it would not
prove the general framework or rewrite the original evidence.

## Why this case is useful

It demonstrates that a repeated request can be salient without becoming
independent corroboration, that a specialist note can qualify rather than
decide, that a staffing possibility is not permission, and that the missing
baseline matters. It also shows a case where the lightweight route may be
enough; a full system would be disproportionate until a pilot is actually
authorized.
