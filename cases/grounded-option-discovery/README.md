# A better way to remember a decision

Status: **CONSTRUCTED ILLUSTRATION / NOT A STUDY OR PRODUCT RESULT**.

A small team asks for a better way to carry decisions between AI tasks. The
obvious proposal is a new searchable memory database. It sounds reasonable:
more memory should mean less repeated explanation.

Before choosing a database, the team looks at the work that keeps getting
lost. In this illustration, the supplied project already has versioned files,
stable decision IDs, a correction history, and an append-only event record.
The missing piece is a short route to the current decision and the evidence
that supported it. Those existing capabilities are stipulated case facts, not
claims about every team's tools.

An unexpected comparison changes the candidate set. How does a well-maintained
library catalogue help a reader find the right edition without becoming a
second copy of every book? The transferable part is the pointer: identity,
edition, location, and enough context to decide whether to open it. The team
can try a small reading index over the records it already owns.

That produces a concrete new option: a decision entry containing the question,
the chosen route, a pointer to the exact supporting version, and the condition
that would reopen the decision. Corrections stay in the original record. The
index can be rebuilt and discarded.

The comparison also has limits. A library pointer does not tell us whether a
decision was sound. A changed file can make an old pointer stale. Search may
still fail if the question is expressed differently. The proposed index needs
a current-source check and a small retrieval trial before anyone calls it
useful. It must preserve access and reuse permissions.

For the supplied case, the next authorized local step is to assemble one
pointer entry and check whether it resolves to the right decision and version.
There is no reason yet to acquire new sources or build another writable memory
authority. If the existing files already answer the question easily, stop with
them. If repeated retrieval failures remain, compare a thin index with an
existing search tool using the same tasks and effort limits.

The discovery here is an additional feasible route, followed by a reasoned
selection. F1 widens where the team looks; F5 transfers a useful structure;
F2 tests what the comparison can support; F4 preserves correction and missing
state. F6 would require a later observed outcome. F3 adds nothing to this
single-decision case. None of the six questions is a box to fill automatically.

This illustration predicts neither time saved nor better decisions. Its value
as an example is that scrutiny leaves room for a useful unfamiliar option,
then makes that option earn its place.
